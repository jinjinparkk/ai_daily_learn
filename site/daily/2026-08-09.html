오늘의 기초 · Fundamentals

LLM 에이전트와 도구 사용 LLM Agents & Tool Use
이게 뭐야? · What is it
ENAn LLM agent is a language model that can plan, take actions, and use external tools to complete a goal, not just produce a single reply.
KOLLM 에이전트는 단일 답변만 내놓는 것이 아니라, 목표를 완수하기 위해 계획을 세우고 행동하며 외부 도구를 사용할 수 있는 언어 모델입니다.
ENTool use means the model can call functions such as a search engine, a calculator, a code runner, or an API to get information or change the world.
KO도구 사용이란 모델이 검색 엔진, 계산기, 코드 실행기, API 같은 기능을 호출해 정보를 얻거나 세상을 바꿀 수 있다는 뜻입니다.
ENTogether, these turn a passive text generator into an active problem solver that works in steps.
KO이 둘이 합쳐지면 수동적인 텍스트 생성기가 단계별로 일하는 능동적인 문제 해결자로 바뀝니다.
작동 원리 · How it works
ENFirst, the agent receives a goal and breaks it into smaller steps, a process often called planning.
KO먼저 에이전트는 목표를 받아 더 작은 단계들로 나누는데, 이 과정을 흔히 계획 수립이라고 부릅니다.
ENNext, it decides whether it needs a tool, and if so, which tool and with what inputs.
KO다음으로, 도구가 필요한지, 필요하다면 어떤 도구를 어떤 입력으로 쓸지 결정합니다.
ENThe tool runs and returns a result, which the agent reads as new information called an observation.
KO도구가 실행되어 결과를 반환하면, 에이전트는 이를 관찰이라 불리는 새로운 정보로 읽어 들입니다.
ENThe agent then reasons about the observation and decides the next action, repeating this loop until the goal is met.
KO그 후 에이전트는 관찰 내용을 바탕으로 추론하고 다음 행동을 결정하며, 목표가 달성될 때까지 이 순환을 반복합니다.
ENThis think-act-observe cycle is the core pattern behind most modern agent frameworks.
KO이 '생각-행동-관찰' 순환은 대부분의 최신 에이전트 프레임워크가 따르는 핵심 패턴입니다.
ENMemory can be added so the agent remembers earlier steps and results across a long task or even across sessions.
KO메모리를 더하면 에이전트는 긴 작업 내내, 심지어 여러 세션에 걸쳐 앞선 단계와 결과를 기억할 수 있습니다.
🧩 비유로 이해 · Analogy
ENThink of an agent like a chef with a recipe goal: it plans the dishes, reaches for tools like a knife or oven, tastes the result, and adjusts the next step until dinner is ready.
KO에이전트는 요리 목표를 가진 요리사와 같습니다. 요리를 계획하고, 칼이나 오븐 같은 도구를 집어 들고, 결과를 맛보며, 저녁이 완성될 때까지 다음 단계를 조정합니다.
기본 용어 · Key terms
Agent (에이전트)목표 달성을 위해 스스로 계획하고 행동하는 AI 시스템
Tool call (도구 호출)모델이 검색·계산·API 같은 외부 기능을 실행하도록 요청하는 것
Observation (관찰)도구 실행 후 에이전트가 받아 다음 판단에 쓰는 결과 정보
Planning (계획 수립)큰 목표를 실행 가능한 작은 단계들로 나누는 과정
Memory (메모리)이전 단계·결과를 저장해 이후 판단에 활용하는 저장 공간

오늘의 핵심 개념 · Key Concept

에이전트 평가 Agent Evaluation
ENBecause agents act over many steps, measuring how good they are is much harder than scoring a single answer.
KO에이전트는 여러 단계에 걸쳐 행동하기 때문에, 성능을 측정하는 일이 단일 답변을 채점하는 것보다 훨씬 어렵습니다.
ENComparing two agents often requires many trials, since luck and randomness can hide the true difference in skill.
KO두 에이전트를 비교하려면 여러 번의 시도가 필요한데, 운과 무작위성이 실제 실력 차이를 가릴 수 있기 때문입니다.
ENEach trial can cost real money, model inference time, or expert effort, so efficient evaluation matters.
KO각 시도는 실제 비용, 모델 추론 시간, 전문가의 노력을 소모하므로 효율적인 평가가 중요합니다.
ENNew methods aim to stop as soon as there is enough evidence, while keeping statistical guarantees valid.
KO새로운 방법들은 통계적 보장을 유효하게 유지하면서도 충분한 증거가 모이는 즉시 평가를 멈추는 것을 목표로 합니다.
ENThe quality of the benchmark itself also matters: a weak benchmark leads to unreliable conclusions.
KO벤치마크 자체의 품질도 중요합니다. 부실한 벤치마크는 신뢰할 수 없는 결론으로 이어집니다.
왜 지금? · Why now
ENAs agents move into real products, cheap and trustworthy evaluation has become a bottleneck for safe deployment.
KO에이전트가 실제 제품으로 들어오면서, 저렴하고 신뢰할 수 있는 평가가 안전한 배포의 병목이 되고 있습니다.
