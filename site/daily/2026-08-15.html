오늘의 기초 · Fundamentals

손실 함수 Loss Function
이게 뭐야? · What is it
ENA loss function is a formula that measures how wrong a model's prediction is compared to the correct answer.
KO손실 함수는 모델의 예측이 정답과 비교해 얼마나 틀렸는지를 측정하는 수식입니다.
ENIt turns the vague idea of 'a bad prediction' into a single number that the computer can work with.
KO'예측이 나쁘다'라는 모호한 개념을 컴퓨터가 다룰 수 있는 하나의 숫자로 바꿔 줍니다.
ENDuring training, the goal is simple: make this number as small as possible.
KO학습 과정에서 목표는 단순합니다. 이 숫자를 가능한 한 작게 만드는 것입니다.
작동 원리 · How it works
ENFirst, the model makes a prediction from the input data.
KO먼저 모델이 입력 데이터로부터 예측을 만듭니다.
ENThe loss function then compares that prediction to the true label and outputs an error value.
KO그다음 손실 함수가 그 예측을 실제 정답과 비교해 오차 값을 출력합니다.
ENA large loss means the model is far off, while a loss near zero means the prediction is close to correct.
KO손실이 크면 모델이 많이 틀린 것이고, 손실이 0에 가까우면 예측이 정답에 가깝다는 뜻입니다.
ENThe training algorithm uses the slope of the loss to decide how to adjust the model's weights, a process called gradient descent.
KO학습 알고리즘은 손실의 기울기를 이용해 모델의 가중치를 어떻게 조정할지 결정하는데, 이를 경사 하강법이라고 합니다.
ENDifferent tasks use different loss functions: mean squared error for predicting numbers, and cross-entropy for classification.
KO과제마다 다른 손실 함수를 씁니다. 숫자를 예측할 때는 평균 제곱 오차를, 분류에는 교차 엔트로피를 사용합니다.
ENThis measure-and-adjust cycle repeats many times until the loss stops improving much.
KO이 '측정하고 조정하는' 과정을 손실이 더 이상 크게 줄지 않을 때까지 여러 번 반복합니다.
🧩 비유로 이해 · Analogy
ENThink of the loss function as a golf scorecard: fewer strokes means you are closer to the hole, and every swing tries to lower that score.
KO손실 함수는 골프 스코어카드와 같습니다. 타수가 적을수록 홀에 가까운 것이고, 매 스윙은 그 점수를 낮추려는 시도입니다.
기본 용어 · Key terms
Ground Truth (정답 라벨)모델이 맞혀야 하는 실제 정답 데이터.
Mean Squared Error (평균 제곱 오차)예측값과 실제값 차이의 제곱을 평균낸 손실로, 회귀 문제에 주로 사용.
Cross-Entropy (교차 엔트로피)예측한 확률 분포가 정답과 얼마나 다른지를 재는 손실로, 분류 문제에 주로 사용.
Gradient (기울기)손실을 줄이려면 가중치를 어느 방향으로 바꿔야 하는지 알려 주는 값.
Optimization (최적화)손실을 최소화하도록 모델 파라미터를 조정하는 과정.

오늘의 핵심 개념 · Key Concept

검증된 코드 생성 Verified Code Generation
ENMost AI coding agents produce code without any proof that it actually meets the requirements.
KO대부분의 AI 코딩 에이전트는 요구사항을 실제로 충족한다는 증명 없이 코드를 생성합니다.
ENVerified code generation asks the agent to produce both the implementation and a machine-checked proof that it is correct.
KO검증된 코드 생성은 에이전트에게 구현 코드와 함께, 그것이 옳음을 기계가 확인할 수 있는 증명까지 만들도록 요구합니다.
ENThis proof is written in a formal language and checked automatically, so correctness is guaranteed rather than merely assumed.
KO이 증명은 형식 언어로 작성되어 자동으로 검증되므로, 정확성이 단순히 가정되는 것이 아니라 보장됩니다.
ENThe hard part is making implementation and proof choices agree with each other across a whole multi-module codebase.
KO어려운 점은 여러 모듈로 이루어진 전체 코드베이스에서 구현과 증명의 선택이 서로 일관되게 맞물리도록 하는 것입니다.
ENNew benchmarks like Vero test whether agents can handle this at the level of real repositories, not just single functions.
KOVero 같은 새로운 벤치마크는 에이전트가 단일 함수가 아니라 실제 저장소 수준에서 이를 해낼 수 있는지 시험합니다.
왜 지금? · Why now
ENAs AI writes more production code, being able to prove correctness is becoming essential for trustworthy software.
KOAI가 실제 서비스 코드를 점점 더 많이 작성하면서, 정확성을 증명할 수 있는 능력은 신뢰할 수 있는 소프트웨어를 위해 필수가 되고 있습니다.

형식적으로 검증된 코드에는 명세를 충족한다는 증명이 함께 딸려 옵니다.
long-horizon
장기 지평의, 여러 단계에 걸친 긴 과정을 다루는
“Long-horizon tasks require the model to stay consistent over many steps.”
장기 지평 과제는 모델이 여러 단계에 걸쳐 일관성을 유지하도록 요구합니다.
speculative decoding
추측적 디코딩, 여러 토큰을 미리 생성하고 병렬 검증해 속도를 높이는 기법
“Speculative decoding accelerates generation without changing the output.”
추측적 디코딩은 출력을 바꾸지 않으면서 생성 속도를 높입니다.
interpretability
해석 가능성, 모델의 내부 작동을 이해할 수 있는 정도
“Interpretability research tries to explain what each feature inside a model means.”
해석 가능성 연구는 모델 내부의 각 특징이 무엇을 의미하는지 설명하려 합니다.
on-device
온디바이스, 서버가 아닌 사용자 기기에서 직접 실행되는
“On-device inference lets a large model run locally with little memory.”
온디바이스 추론은 큰 모델을 적은 메모리로 로컬에서 실행하게 해 줍니다.
