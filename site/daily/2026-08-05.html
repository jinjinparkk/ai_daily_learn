오늘의 기초 · Fundamentals

벡터 DB와 유사도 Vector Database & Similarity
이게 뭐야? · What is it
ENA vector database stores data as lists of numbers called vectors, which capture the meaning of text, images, or audio.
KO벡터 데이터베이스는 데이터를 '벡터'라 불리는 숫자 목록으로 저장하며, 이 벡터는 텍스트·이미지·오디오의 의미를 담아냅니다.
ENInstead of matching exact words, it finds items whose meanings are close to your query.
KO정확한 단어를 일치시키는 대신, 의미가 여러분의 질의와 가까운 항목을 찾아줍니다.
ENThis makes it the foundation of modern semantic search and retrieval-augmented generation (RAG).
KO이 덕분에 벡터 DB는 현대적 의미 기반 검색과 검색증강생성(RAG)의 토대가 됩니다.
작동 원리 · How it works
ENFirst, an embedding model converts each piece of data into a vector of hundreds of numbers.
KO먼저 임베딩 모델이 각 데이터 조각을 수백 개의 숫자로 이루어진 벡터로 변환합니다.
ENSimilar meanings produce vectors that sit close together in this high-dimensional space.
KO비슷한 의미는 이 고차원 공간에서 서로 가까이 위치한 벡터를 만들어냅니다.
ENTo measure closeness, we often use cosine similarity, which compares the angle between two vectors.
KO가까운 정도를 재기 위해 흔히 두 벡터 사이의 각도를 비교하는 코사인 유사도를 사용합니다.
ENWhen you ask a question, your query is also turned into a vector and compared against stored ones.
KO질문을 하면 그 질의 역시 벡터로 바뀌어 저장된 벡터들과 비교됩니다.
ENThe database returns the nearest neighbors, meaning the items with the highest similarity scores.
KO데이터베이스는 가장 가까운 이웃, 즉 유사도 점수가 가장 높은 항목들을 반환합니다.
ENTo stay fast over millions of items, it uses approximate nearest neighbor (ANN) indexes instead of checking everything.
KO수백만 개 항목에서도 빠르게 동작하도록, 전부 확인하는 대신 근사 최근접 이웃(ANN) 인덱스를 사용합니다.
🧩 비유로 이해 · Analogy
ENThink of it like a library where books are placed on shelves by topic, so similar ideas naturally end up as neighbors.
KO주제별로 책을 서가에 꽂아 비슷한 아이디어가 자연스럽게 이웃이 되는 도서관을 떠올려 보세요.
